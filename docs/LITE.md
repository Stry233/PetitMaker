# PetitMaker (Lite) for Xiaohongshu and Bilibili Toy

PetitMaker (Lite) (谷地工坊 (Lite)) is an offline edition packaged for one of two hosts: Xiaohongshu’s 小工具 container and Bilibili Toy (哔哩哔哩 Toy). It shares PetitMaker’s map rules, terrain and object tools, custom planets, annotations, undo and redo, local autosave, seven interface languages, and 2D and supported-device 3D views.

## Build and preview

Use the same Node version and dependencies as the web edition. Lite builds also use the installed development dependencies to convert bundled images to WebP and lower Unicode regular expressions.

Packaged versions use the computed version with a `-lite` suffix, such as `1.3.10-lite`. Local development builds also retain `-dev`.

```sh
npm ci
npm run build:lite
npx vite preview --mode lite
```

`PETIT_LITE_HOST` selects the host, `xhs` (the default) or `bilibili`; set it for the build, the packaging and the preview alike, for example `PETIT_LITE_HOST=bilibili npm run build:lite`. An unknown host fails the build. Each host builds into its own `dist-lite/<host>/`, so building one never removes the other.

Packaging writes a versioned ZIP named `petitmaker-<version>-lite-<host>-<hash>.zip`, the Xiaohongshu one to `artifacts/lite/` and the Bilibili one to `artifacts/lite/bilibili/`. Each ZIP has a JSON manifest containing its host, version, source build, byte size and SHA-256 checksum; `latest.json` in the same folder identifies that host's latest build. A ZIP named before there were hosts, `petitmaker-<version>-lite-<hash>.zip`, still reads as a Xiaohongshu one. Identical builds reuse the same file, while changed contents get a new hash and preserve previous builds. The artifacts directory is ignored by Git, and ZIPs are excluded from the public source snapshot.

The ZIP has one `index.html` at its root and relative references to its bundled resources. Upload the Xiaohongshu ZIP through Xiaohongshu’s tool uploader and the Bilibili ZIP through Bilibili Toy’s publishing page. An ordinary browser can preview and edit the map; saving to an album and creating a note become available when the Xiaohongshu container provides its SDK, and on Bilibili saving to the album and sharing a link work inside the Bilibili app.

`npm run dev:lite` starts the development server. Its policy permits local development scripts and hot reload. Test the production ZIP or production preview when checking the offline restrictions. `npm run build` continues to create the full web edition in `dist/`.

## Features and limits

| Area | Lite behavior |
| --- | --- |
| Editing | Terrain, roads, objects, layers, annotations, undo and redo use the shared editor and game rules. Change a planet offers the built-in planets and My planets, including drawing your own planet; planet file import and export are omitted along with JSON files. |
| Viewing | 2D works with WebGL or the Canvas2D fallback. 3D requires WebGL2. Settings retains Auto, Full and Light. Auto starts with shadows and multisampling disabled; Full uses a 1024-pixel shadow map and bounded 2-sample antialiasing. Drawing buffers start at at most 1× density and approximately one million pixels. On hardware with sustained rendering headroom, Auto and Full raise clarity up to the web edition’s device-density cap of 2×, with an eight-million-pixel ceiling. Light stays conservative. Sustained slowdown reduces effects and resolution, and stops further increases for that scene. Resource pressure lowers quality when frames exceed the rendering time budget. Only sustained slow rendering after reaching the minimum quality returns to 2D; cursor redraws and scene complexity alone do not force that fallback. |
| Saving | Local autosave restores the map and available undo history on the same device. Container data can be cleared, so this is not a portable backup. |
| Pictures | The shared image composer provides title and description fields, four output sizes, layer previews, editable 3D shots, grid and annotation controls, and a customizable footer. Lite’s Share Image and Plain Image presets set presentation defaults; Share Image enables PetitGlyph by default so the picture can carry an editable map. Plain Image leaves it out by default. On Xiaohongshu, Save to album and Create a note use the injected Xiaohongshu SDK after the export acknowledgement; opening the composer does not publish the note. On Bilibili, Save picture keeps the picture in the Bilibili app's album, or downloads it in a web browser, and the picture's footer carries the Toy's own QR code (see Bilibili Toy). |
| Imports and portable saves | On Xiaohongshu, Import opens PNG, JPEG and WebP pictures containing PetitGlyph, previews the recovered map and asks before replacing the current one; save a Standard or larger picture with Importability enabled to include PetitGlyph. Bilibili Toy takes no picture a visitor uploads, so its package has no Import; in the Bilibili app, Share link sends a link that opens the map instead. JSON file import/export and clipboard share codes are omitted. |
| Generation | Planet, Maze, Letter and Picture retain recipe thumbnails, settings and region selection, and Planet and Maze their custom seeds. Previews run one at a time on the main thread. Letter's own words pass the text check once committed: the local check in both packages, then Bilibili's own in the Bilibili package. Picture builds from the game character portraits the package carries; neither package takes a picture of the visitor's own. Illustration is omitted. |
| Text check | Every text a player types, and every such text a file or a saved map brings, passes the local text check on the page, as in the web edition; the Bilibili package then passes it to Bilibili's own check (see Bilibili Toy). A picture's map is not checked automatically. |
| Assistant | AI assistant and provider settings are omitted. |
| Platform features | No external navigation, clipboard, full-screen requests, network calls, Web Workers or WebAssembly. No browser downloads, apart from Save picture in the Bilibili package outside the Bilibili app. |
| Guidance | The welcome tips (without demonstration reels, which the offline package has no room for), Show the welcome tips in Settings, searchable Help and contextual help cover Lite’s available editor features. About uses the shared web-edition layout and document reader, with branding, build details, team and community credits, a selectable feedback address and offline licenses. External navigation, clipboard actions, sponsorship links and web-only policy pages are omitted. |

Xiaohongshu client 9.37 or later is required for the data-URI images used by map previews and recipe thumbnails.

In a portrait container Lite shows the editor's upright arrangement, as the web edition does on an upright screen. Safe areas are reserved outside the editor; while a text field has focus, the layout fits above the keyboard. In the Bilibili app the package asks the container for landscape immersive mode on start, listening to the container first, since the request resolving does not mean the mode took effect; once a state reports that mode it lays the page out in the viewport the container reports, inside its safe area and below the top bar, and where none does (an older client, the web) it keeps the layout above. Nothing else requests a native orientation lock. Lite uses system fonts and resized WebP art. Its initial 3D profile is conservative; resolution can increase after observing smooth interaction.

## Container integration

The implementation follows the [official mini-tool ZIP builder 1.10.0](https://fe-static.xhscdn.com/minitool/20261105143522/minitool-zip-builder-1.10.0.skill) and the [mini-tool documentation](https://miniapp-sandbox.xiaohongshu.com/minitool/doc) of November 6, 2026, with its ES2017 / Chrome 61 baseline, classic scripts, relative packaged resources and 10 MiB upload limit. Only pictures go in the package's `assets/` folder, which clients from 9.53.3 may serve from afar under the documentation's static resource optimisation; the entry script and stylesheet sit in the package root. A picture that fails to load there shows a placeholder and loads again when the connection returns, when the tool comes back to the front, or on its own after a while. The earlier [小工具容器技术规范与 API 文档](https://fe-video-qc.xhscdn.com/fe-platform-file/104101b8323q4m0uaga06277180ac7t8006ptl0e12ek1g#s5), updated August 11, 2026, provides additional background. The container supplies `window.xhs.miniTool`; the package does not fetch an SDK.

The image adapter sends a PNG data URI to `writeTempFile` when available and passes the temporary path to `saveImageToPhotosAlbum`. `postNote` receives the complete PNG data URI directly. If the temporary-file helper is absent, the documented data-URI input is used directly. Temporary paths are never persisted. No note title, content or tags are filled automatically. SDK failures leave the editor and preview available for another attempt.

The container owns the production content security policy; the ZIP contains no CSP meta tag. The local verification server enforces an equivalent offline policy through an HTTP header. Build aliases exclude the assistant surfaces and replace worker entry points with main-thread implementations. Packaging rejects unsupported file extensions and worker/model runtime files. Bundled dependency license text may mention capabilities that this edition does not use.

Before submitting, test the ZIP in the real Xiaohongshu container on iOS and Android: cold launch, pictures after reopening offline, touch editing, undo, restoring after closing the tool, 2D and 3D, Planet, Maze, Letter and Picture thumbnails and application, PetitGlyph export and image import, portrait touch and pinch gestures, safe areas, the software keyboard, all window sizes, album permission rejection and retry, and cancelling or completing the note composer. Browser tests with an injected SDK double verify adapter calls but cannot establish native permissions, platform acceptance or device performance.

## Bilibili Toy

Bilibili serves a Toy at `https://www.bilibili.com/toy/<slug>/index.html`, so every reference in the package stays relative; none starts at the site root. The entry page loads the Toy SDK from `https://s1.hdslb.com/bfs/seed/toy/app/sdk/toy-sdk.js`, which defines `window.toy`, ahead of the app’s script; it is the package’s only external script. The platform takes an entry `index.html` of at most 1 MB uncompressed and a package of at most 50 MB, allows no iframe of another site and no link off Bilibili, and the package carries no `<base>` element and no CSP meta tag. Text a player types passes the local text check, run on the page, and then the Toy SDK’s `checkInputSafety`, once for each text committed and under a scene naming its kind (`title`, `description`, `footer`, `tag`, `blueprint-name`, `blueprint-folder`, `planet`, `stencil`); the names an imported blueprint or a restored map brings, `blueprint-author` among them, are checked the same way before they show. A rejected text is refused like a locally refused one. `unavailable`, a check that did not run, is never a pass: the text waits and the surface offers to check again. A text over the SDK’s 16384 UTF-8 bytes is never sent. Bilibili forbids names a player makes up, so the save step's author takes no typing: turning Anonymous off asks `getUserProfile` for the player's nickname, the platform asking the player's consent the first time, and the blueprint stays anonymous when none comes. Only the nickname is read; the Toy user id is never kept or logged. The Bilibili package otherwise keeps the Xiaohongshu package’s content rules: classic scripts, no workers, no network calls of its own and the same file types. It has no 200-file limit, and its `assets/` folder keeps the same layout without the pictures-only rule.

The share window shares three ways through the SDK, whose every call, the text check, nickname and screen mode included, goes through `platform/host/host-bridge-bilibili.ts`, and asks `toy.isSupport` which of them the page has, since the Bilibili app and a web browser answer differently. Save picture passes the PNG as `base64Data` to `toy.saveImageToAlbum` in the app; a data URI over 5,000,000 characters (the SDK's 5 MB limit, read strictly) is never sent, and the window offers the largest smaller size expected to fit. In a web browser, which has no album, it downloads the picture, the one download the package makes (`SUPPORTS_PICTURE_DOWNLOAD`); its HTML still carries no `download` attribute. Share link, shown only in the app, opens the app's share panel through `toy.share({ path: 'index.html?map=<code>' })`. The code is the PetitGlyph payload in base64url, about 200 characters for an empty planet, 1,300 to 2,700 for a generated one and up to 6,000 for a dense hand-built one; the payload is already entropy coded, so a denser text would gain under 4 %. A link is offered for a path of at most 8,000 characters, which every measured map stays under; a larger map is told to share a picture instead. The link carries the map's title and description, so Share link sends them through the same text check as Save picture first: a refused text holds the link, and a check that could not run holds it until the player checks again. Opening the Toy with `?map=` shows the linked map in the import confirmation once the saved-session question is settled, takes the parameter off the address, and replaces the open map only on confirm. The picture's footer QR comes from `toy.getQrCode`: it points at the map's link where that QR stays readable at the footer's size (two pixels a module), which a Native picture reaches for a link of up to about 2,300 characters, and at the Toy's entry page otherwise, as at every preset size.

Before submitting, test the Bilibili ZIP in the Bilibili app on iOS and Android and in a web browser: saving to the album with permission granted, refused and granted again, a Native picture over the album's limit, the share panel and a shared link opened in another account, a picture's QR scanned from the album, and the download in a web browser. The browser campaign's `window.toy` double answers like the app for these calls but cannot establish native permissions, the share panel or how long a link the platform accepts.

## Validation limits

The ZIP size check and bundled-script checks run during `npm run build:lite`. The build rejects module syntax, disallowed runtime calls, oversized embedded base64 and ZIPs over the host’s limit: 10 MiB for Xiaohongshu, 50 MB and an entry page over 1 MiB for Bilibili. Each platform forbids naming another, so packaging also rejects a package that names another host's platform: every host in `src/platform/build/lite-hosts.ts` lists its platform's names as each locale writes them and its link domains, and the packager reads every HTML, JavaScript, CSS, JSON and SVG file and every file name of the other host's package for them, in any case, skipping encoded picture bytes. Each bundle keeps only its own host's entry of that table, and the legal documents only the web edition shows stay out of both bundles. The official size audit can still warn above its recommended 2 MiB target or about large uncompressed JavaScript. The single script includes the editor, both renderers, seven locales and map templates; compression does not eliminate their parse and memory cost.

Desktop browser checks and tests with selected modern APIs removed are not physical-device validation. Chrome 61 CSS compatibility, Xiaohongshu native permissions and low-end device performance require testing in the official simulator and real iOS / Android container.

## Maintaining both editions

The ordinary web and offline Lite editions are build targets of the same source tree. `npm run build` preserves the web entry point, modern bundling, assets and graphics settings; `npm run build:lite` selects the container entry point, offline adapters and Chrome 61 compatibility transforms. Legacy syntax support does not determine rendering resolution.

`platform/build/edition.ts` declares platform capabilities from the edition and, in Lite, the host that `platform/build/lite-hosts.ts` describes; a record a host may lack names the capability it needs. `scripts/edition-build.mts` selects build adapters, each host's own ahead of the shared ones, and rejects Lite adapters in a web bundle. Keep host operations behind those boundaries, and keep map rules, editing tools, session persistence and reusable interface components shared. The app roots own their distinct startup and host surfaces; both mount the same editor session (`editor/session/install.ts`), which saves maps, notes, history and cameras, and restore a saved session through `editor/session/restore.ts`. `ui/shell/windows/EditorWindows.tsx` wires common windows and planet changes, with host feedback supplied by each edition. Export preset behavior belongs in the edition's review policy (`editor/review/edition-review.ts` and its Lite twin), beside review and stylization availability.

Only the Lite build applies compatibility rewrites. Offline dependency substitutions name specific files; a newly introduced network or dynamic-code call fails packaging rather than being silently rewritten. CSS fallbacks activate only when the corresponding feature is absent and revisit affected DOM subtrees. Modern browsers retain their native layout behavior.

Both build commands work from a clean checkout with `npm ci`. `scripts/lite-validation.mts` owns final script and resource validation; `lite-package-core.mts` owns file collection, deterministic archive creation and versioned storage; `package-lite.mts` supplies the build identity and reports the result. Validation checks the collected bytes for HTML, CSS and SVG resource paths, script syntax, disallowed calls, embedded resource limits and ZIP size, and reports size advisories. No downloaded skill or local preview directory is needed. The shared tests guard every change to shared code, and the Lite build with its browser checks runs before every release; device validation remains necessary before XHS submission.
